# 知识抽取提示词

## keywords
在企业智能客服场景中，用户和客服进行对话，客服在理解用户问题后，生成query检索案例库，得到一个能解决用户问题的案例。但是客服可能不具有企业内部知识，导致生成的query检索不到目标案例。
你负责从检索失败数据中发现query生成遗漏的专有关键词。输入是同一个目标案例的一批完整对话、目标案例标题、内容和已生成的 queries。
gt_case_title 和 gt_case_content 是这批对话共同对应的目标案例标题和正文，仅在顶层提供一次；records 中每条包含一段完整对话 chat_content 及其对应的 queries。
关键词需要从 GT 标题中抽取，一般是被query忽略，导致检索不到GT案例。关键词一般是内部的软件名、产品名、术语等。
不要抽取通用词和常见词，如win11，安装，软件，要抽取你感到陌生、不常见的企业内部词汇。
仅抽取一个关键词，关键词不一定是一个名词，也可以是较长的复合短语。
不要编造关键词。
再抽取完关键词后，结合对话、案例标题和内容，推测这个关键词在企业内部的含义，得到对这个关键词的描述解释。
请先分析，然后用json代码块包裹你的结果
...(analyse)
```json
{"keywords": "关键词", "desc": "对这个关键词的描述解释", "reason":"依据"}
```
没有符合条件的关键词时，keywords 输出空字符串，并在 reason 说明原因。

## merge

输入每项为“关键词：描述解释”。你的任务是结合描述解释判断哪些关键词是说的一件事情。常见情况包括：关键词仅是大小写、连接符、空格等细微差别；仅是多或者少了一两个字，核心概念一致。可以结合描述解释，判断关键词是否是说的一件事情。
把说同一件事情的关键词放在同一个组，含义不同的分开。
每个输入项（包含关键词和描述解释的完整字符串）必须且只能出现一次；不能新增、改写或遗漏。每组选择一个组内完整输入项作为 keyword，keywords 列出该组全部完整输入项（含代表词），reason 简述依据；无法合并的词单独成组。
请先进行分析，确定好每个词的分组，确定没有词遗漏判断了
然后输出用代码块包裹的 JSON：
```json
{"groups":[{"keyword":"组内代表词","keywords":["组内代表词","同义词"],"reason":"分组依据"}]}
```
(这里的词指的就是包括关键词和描述解释的输入项)

## filter

判断候选关键词是否已包含在已有知识条目中。existing_knowledge 是已有知识条目。
已有知识如果已经包含该词、明确的同义词、全称/缩写或中英文别名，并描述了它的使用场景，则 covered=true。不要求字面完全一致。不能因为两个词属于同一大类软件就认为已覆盖。没有覆盖时 covered=false。
候选关键词输入形式为“关键词：描述解释”，描述解释可帮助你进行判断。
仅输出 JSON：{"covered":true,"matched_knowledge":"引用实际已有条目，未覆盖时为空字符串","reason":"判断依据"}

## extract
在企业智能客服场景中，用户和客服进行对话，客服在理解用户问题后，生成query检索案例库，得到一个能解决用户问题的案例。但是客服可能不具有企业内部知识，导致生成的query检索不到目标案例。

现在得到了一批次检索失败的“用户对话—推荐 GT 案例标题”和生成的queries，以及这个批次对应的关键词及其描述解释，你需要从中抽取知识。
你需要充分归纳分析对话，理解关键词是什么，明确当用户提到什么时，应该考虑该关键词。
knowledge 写成“关键词：(是...)，当用户提到...时可考虑‘关键词’”的一条完整知识，不能输出案例 ID、隐私或具体个人信息。不要仅仅罗列出现在对话中的适用场景，要加以理解归纳，再给出具有泛化性的说明。
